## 1. 已钉住的事实

- `.mesh` 头：`+0x00` 起 0x40 字节是
  `Copyright 2013-2200 http://www.julegame.com/ Corporation. All rights Reserved`，
  `+0x44` 是 ASCII 标签 `mesh`，`+0x4c` 又出现一次 `mesh`。
- 这条版权串在 exe 里**只有一处**：`0x140ef2e90`，被 5 个函数引用：
  `sub_14070FB70`(0x52a)、`sub_14072F6F0`(**已知的 .ani 装载器**)、
  `sub_1407304C0`(资产装载派发)、`sub_140736070`(0x6ed)、`sub_1407A6E40`(0x5e9)。
- 这 5 处全是 **`strncpy(Destination, "Copyright...", 0x40)`——写头，不是读头**，
  所以它们是序列化/构造端，读取端不碰这条串（很可能整段 0x40 被当不透明前缀 memcpy）。
- `sub_140736070` 里有 `a1+196` = 顶点数、`a1+496` 与 `a1+520` 按 **`3 * count`** 分配
  （位置/法线/切线三组）→ 这一族函数就是网格对象本体，装载器在同一模块
  （`0x14072F000..0x140745000`，40 多个 ≥500B 的函数）。
- 类型注册：`sub_1400E0840` 用与 `path_hash` 的 h1 道**同型的哈希循环**（初值 1074195201）
  算 `"mesh"` 的 id，再 `qword_1410AD918 = sub_1402E0480("mesh", 4, hash)`。
  → `qword_1410AD918` 就是 mesh 类型描述符。

2. **反向找读取端**：`sub_14072F6F0`(.ani) 的兄弟函数按同一形状找——

   用 `find_bytes` 搜 `6D 65 73 68` 在 `.text` 里的**立即数形态**（`cmp ..., 6873656Dh`）

3. **拿到读取端后**：只看它从 buf 的哪个偏移取哪个字段，对照我们

## 追加（同班午后）：静态这条**已判死**，别再走

四枪都打在墙上，证据如下：

1. `qword_1410AD918`（"mesh" 注册项）与 `qword_1410ABB38` 在 IDB 里读出来都是
   **`0xFFFFFFFFFFFFFFFF`**——注册是 `sub_1400E0840` 这类**启动期 init 函数**在运行时写的
   （末尾还挂着 `atexit`），静态库里只有占位。
2. 按扩展名造对象的工厂 `sub_1409A47F0`（0x59d，`.text` 里唯一出现
   `cmp dword ptr [rax], 6873656Dh` 的函数）看清了：它判后缀（`"mdl"` / `"mesh"` …），
   然后 `(*(*qword_1410A7DD8 + 48))(qword_1410A7DD8, <小整数类型 id>)` 造实例
   （mdl 那一支传 55，另有传 0 与 80 的支）。**类型 id 是运行期整数，创建者在运行期表里**，
   静态拿不到 id→类 的映射。
   （顺带：工厂里那圈 `v ^ 0x4006EB05` 的哈希是**字符串查表用的**，不是类型 id。）
3. 注册表查找函数 `sub_140136890` 是**开放定址哈希表**（`qword_1410B5C38` 桶数组，
   `16LL * (id & 0x1FFFF)`，节点里存名字长度与 id）——桶由 `sub_1401375C0` 首次使用时分配，
   所以静态库里**没有可读的表体**。
4. 资产装载派发 `sub_1407304C0` 的 callee 清单（`callees{addrs:[...]}` 一发拿全）只有 11 个：
   `sub_14072F6F0`(.ani 装载器)、`sub_1407330B0`(free)、`sub_140136890/9D0/E60/5C0`(注册表)、
   `sub_1400EE110`/`sub_1400F0FA0`(串处理)、`sub_1405E47A0`、`sub_1409A3660`/`sub_1409A81D0`
   （两个都只有 16/26 行，是包装不是装载器）。**派发器自己不调 .mesh 装载器**——
   网格是走类型表分派的，不在这里。

## 所以：要 `.mesh` 装载器只能动态

**动态取表的确切目标**（挂上客户端后一次就够）：

- `qword_1410B5C38` = 注册表桶数组基址，桶数 `0x20000`，每桶 16B（`[ptr, lock]`），
  节点里 `+12` 是名字长度、`+16` 是类型 id、名字指针在节点前部；
  **遍历桶把非空节点全 dump 出来 = 整张「类型名 → id → 创建者虚表」表**。
- `qword_1410A7DD8` = 工厂对象，其虚表 `+48` 槽是 `create(type_id)`，
  dump 这个对象的虚表就能拿到每个类型的构造/装载函数。
- 客户端启动后**先让它跑到能显示任意一只怪**（注册表在首次使用时才建），再读这两个全局。

这一枪和贴图真答案是**同一次实机操作**能一起拿的：绑定时引擎请求的贴图身份
（匿名贴图 hash 从哪来）就在同一条装载路径上。**建议合成一次挂钩会话**，
等用户点头起客户端。

## 待命钩子已经写好了（2026-10-11，只差你启动客户端——我没有擅自起）

`.scratch/dyn/run_dump.py` + `.scratch/dyn/dump_types.js`。用法一条命令：

```bash
python D:/TLGL/.scratch/dyn/run_dump.py        # 先起它，再开客户端，玩到能看见一只怪
```

它自己做完这些：记下已存在的同名 pid → 20ms 一次轮询**新出生**的 `tlbbgl_x64.exe` 立刻 attach
（Windows 上 frida 没有子进程门控，`enable_spawn_gating` 直接抛 NotSupportedError，只能轮询）；
attach 后每 5 秒探一次桶数组，**表一建起来就自动 dump 整表 + 挂上工厂虚表 +48 那槽（create）+ 落报告**
（`.scratch/dyn/out/types_*.md` / `.json`）。前台也可以手敲：`p` 探测 / `d` 整表 / `c` 挂 create / `q` 退出。

三处是按「静态拿不到、动态只能猜一个偏移」的处境设计的，**别把它的输出当成已验证结论**：

1. **基址自检**：RVA 全部按 idb 基址 `0x140000000` 推。脚本先读 `0x140ef2e90` 那条版权串
   （`Copyright 2013-`，全 exe 只有一处），对不上就**拒绝 dump** 并把读到什么报出来——
   否则整套地址会静默全落空，那种假干净最坑。
2. **节点里名字指针的偏移没证**（记录只说「在节点前部」）：`parseNode` 依次试 `+0 / +8 / +24 / +32`，
   只有解出**全可打印 ASCII 且长度 1..63** 才算命中，报告里 `offHits` 会写哪个偏移中了几次——
   第一次真跑之后按命中数把它钉死，别再留着四选一。
3. **每一次读都单独 try**：某桶坏了只记那条的错，整批不崩（失败留现场）。

验到哪一步要说清：**只验了管道**——`--selftest --name notepad` 会自己拉一个记事本，
量「出生轮询 → attach → payload 装载 → RPC → 报告落盘」全通（跑过，报告在
`.scratch/dyn/out/selftest_20261011_1613*.md`），而且模块不存在时每一路都老实报「还没找到模块」而不是崩。
**表有没有真拿到、类型名对不对、贴图身份在不在同一条路径上，一概未验**——那需要客户端。
