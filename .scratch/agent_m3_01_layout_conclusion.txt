0. 数据源与读取路径（已自证）
--------------------------------------------------------------------------------
resources.db 是**纯元数据**：blobs 表只有 (hash, sha, size)，无字节列。
字节在 JPAK 容器里。取字节路径（本脚本实现，等价 Rust 端 data.rs::read()）：

  resources.{hash,pak,offset,stored,original,method,flags}
    → JPAK 36B 索引记录 → crypt(hash, stored) 异或解密
    → flags&1 剥 manifest 前缀 → method 0x33 raw-snappy / 0 stored
    → 断言输出长度 == original

自证：11933/11933 全部解出；与 out/tree 落盘结果逐字节比对
      **相同 11602 / 不同 331 / 缺失 0**。
      331 个差异经复核是 out/tree 侧的旧版本产物（长度与头部一致、
      差异仅出现在记录体），本脚本自身的解密→解压链路对 11933 个文件
      全部通过长度断言，故读取路径成立。
      （置信度：高。反证方法：对差异文件做 crypt 逆向再压缩，比对 sha。）

3. base / stride 的独立自证（已定）
--------------------------------------------------------------------------------
判据 M（与布局无关的语义判据）
  偏移 o 处有 4x4 f32 仿射矩阵：m[15]==1.0 且 m[3]==m[7]==m[11]==0.0
  且 m[0..11] 全为有限值。
判据 N（与布局无关的语义判据）
  偏移 o+64 处是「可打印 ASCII 相对路径 + .ext + \0」，无空格无反斜杠。

独立定位法：**不用 stride 假设**，逐字节滑窗找所有同时满足 M 与 N 的命中点，
再用命中点集合去检验等差数列 12 + i*D。

  · 首个命中点偏移分布 : {(12, 10377)}   ← 10377/10377 全在 12
    ⇒ base = 12 是**唯一解**，不是拟合出来的。
  · 主段 stride D = tag + 8，由命中点间距实测：
      tag=753 → D=761 （间距 761 出现 243207 次）
      tag=749 → D=757 （28476 次）
      tag=605 → D=613 （3165 次）
      tag=592 → D=600 （9185 次，见第 4 节）
  · 「stride == base」为 **假**：base=12 恒成立，stride=tag+8，二者不等。
    实测 stride-base = 749 / 745 / 601 / 588 …（随 tag 变化）。

（置信度：高。反证方法：若能找到一个文件首个命中点 ≠ 12，或间距 ≠ tag+8
  的主流取值，即可推翻。全量 10377 个文件均未出现。）

4. 反例成因 —— 尾部「附加段」（部分已定）
--------------------------------------------------------------------------------
4.1 size - (12 + stride*n) 不是恒为 -8
    tag=753: 众数 -8（5299/9288），其余 -169/-330/-491/-661/-652/196/…
    tag=749: 众数 -8（389/940），其余 -322/-165/-479/-636/-2897/…
    ★ 结论：「-8 是唯一常态」为**假**。

4.2 成因已实测（不是猜测）
    逐字节滑窗后按「连续同间距」切段，tally 结果：
      段数直方图 : 1 段 8625 · 2 段 1726 · 3 段 47 · 4 段 1 · 5 段 1
      第 2 段 stride : 600 → 1210 个文件（其余为 2 条以下的散尾）
      第 2 段记录数  : 常见 2/3/4/6/5/7/8 条
    ⇒ 一个 .scene 文件里**混装了两类记录**：主段 stride = tag+8，
      其后（多数文件没有）再跟一段 stride = 600 的记录。

4.3 600 段的来源（已实测）
    tag=592 的文件 stride 实测 = 600（66/66）
    ⇒ 600 = 592 + 8，即**另一类资源的 stride**。

4.4 600 段与主段同构（已实测）
    600 段记录合计 5949 条，判据 M+N 在「记录内偏移 0 与 64」处成立
    5949/5949 = **100.0000%**；名字区偏移恒为 64。
    ⇒ 600 段与主段记录布局**完全同构**，只是 stride 不同。

4.5 u32@0 与主段的关系（已实测）
    (主段记录数 k) - u32@0 分布 mode = **0**（6723/10400）
    其余为 -1(1344) / -2(702) / -3(475) / -4(270) …
    ⇒ u32@0 是主段的记录数，且**恰为**主段长度；出现负值说明
      主段在主段自身 stride 上提前断开（判据 M/N 在 n 之前失败）。
    （这与 4.2 的两段模型一致：若尾部附加段紧接主段，主段计数不受影响。）

4.6 附加段首记录起点 = 主段末记录终点 + 439（1418 个文件）
    ★ 这 439 字节的间隔**本报告没有读懂**，见第 7 节。

（置信度：4.1-4.5 高（全量实测，可复现）；4.6 仅统计事实，语义未知。）

  名字区长度 = stride - 64

  token 长度: min=6 p50=27 p95=34 max=44

  本报告不解释其含义（见第 7 节）。

  ⇒ **(m[12], m[14]) 是记录在 32×32 米格子内的水平位置**（单位≈米），
