# 重新定位：TLBB 资源浏览器 / 解包预览器

> 文档日期：2026-09-23。仅描述方向与现状，不动代码、不跑构建。

## 1. 一句话定位

TLBB 资源浏览器 / 解包预览器——让人能看懂客户端里到底装了什么，把 PAK/JMT/JBCF 里的模型、贴图、动画、场景直接看懂、预览、导出。

## 2. 为什么转向

之前项目跑偏成「资产知识图谱 / 逆向考古平台」：
从「贴图没有名字」一路追到「为什么这个资源没有身份证」，最后做成了一面考古墙。
那是**研究线**，有价值，但不是产品的第一目标。

用户原话精神：
> 你已经把发动机拆开研究了一遍，但你本来只是想造一辆车。现在重新装车。

结论：发动机（解包/解码/索引技术）已经造好了，现在用它们**装一辆车**——一个能用的资源浏览器。

## 3. 资产盘点：已有什么

按「浏览器需要什么」重新归类。

**直接进产品（普通模式）**
- PAK 解析：JPAK 容器、加密、Snappy、manifest。
- JMT1 贴图解码：BC1/BC3/RGBA32/L8，实测 1792 张真实 codec 与文件头标签不符（已证实，工具无错）。
- JBCF 容器：字符串表即材质槽 / 引用名；.ske 也是 JBCF。
- Catalog：SQLite 145MB，105,327 资源，检索毫秒级——浏览器的索引底座，保留。
- 24,261 张无名贴图全部解码成功（1 张 WebP 失败）；聚族 1,515 组覆盖 5,032 张，孤图 19,228 张（6,669 张是 alpha 全零但 RGB 有内容的遮罩类）。
- `view.exe`：命令行预览器，已验证材质/贴图/骨骼/动作/模型五路输出。

**降级为分析模式（藏起来：高级信息 / 开发者模式）**
- 引用健康度：总引用 98,504 / 已解析 61,408（62%）/ 悬空 14,377。
- 名字→实体命中率：.ske 87% / .mesh 77% / .mtl 73% / .ani 72% / **.tga 0.3%**。
- 悬空引用、证据链、dangling 报告——仅开发者可见，普通用户不该看到。

**封存（不再主动推）**
- 「图片考古墙」「无名资源考古」概念：并入「无名资源浏览模式」，作为普通菜单入口而非研究展示。

## 5. 路线图

### M1 模型预览
- 已有基础：`view.exe` 已解析 .mesh 信封（tag=mesh v=1）与 .mtl 材质槽；
  实测 **.mesh 内不嵌贴图名**，模型→贴图的接线全在 `.mtl`，而 .mtl 槽位已能现场解析。
  .mdl（2,146 个）尚未验证格式，M1 第一步就是解它。
- 要补什么：.mdl 格式解析（骨骼树/动作列表/材质表）、UI 网格渲染、贴图状态面板。
- 验收标准：打开 `w1351_nan.mdl` 能看到骨骼数、动作列表、材质槽与每个槽的贴图状态（缺的显示「缺」）。

### M2 动画时间轴
- 已有基础：`view --type=ani` 已解析信封 tag=ani v=2 + bip01 骨架名；动画列表已知（idle/run/attack/skill）。
- 要补什么：时间轴播放控件、骨架绑定、帧插值预览。
- 验收标准：选 idle/run/attack/skill 任一阵列可连续播放，骨架随帧运动。

### M3 场景浏览
- 已有基础：模型 + 贴图 + 材质槽已可独立预览。
- 要补什么：把多个模型按引用关系组装进场景图，相机漫游。
- 验收标准：加载一个场景描述，能在该场景里走动并看到各模型带贴图呈现。

### M4 导出
- 已有基础：`--png-out` 已验证 PNG 导出（110x152）。
- 要补什么：OBJ / FBX / JSON 三种格式序列化。
- 验收标准：模型导出 OBJ+FBX 可被 Blender 打开；贴图导出 PNG；结构导出 JSON。

## 6. 红线（纪律）

1. **不解出像素就不显示图**——宁可空白，不伪造。
2. **名称用原文**——不臆造"它可能是某角色"，只显示客户端里的真实名字 / hash。
3. **悬空就显示「缺」**——贴图断链是类型性的（.tga 命中率 0.3%，客户端设计阶段没存路径），工具无错，照实标「缺」。
4. **只读**——不修改任何 PAK / Catalog，纯浏览与导出。
5. **不再追身份问题**——「为什么这个资源没有身份证」是逆向研究线，不是产品主线，到此为止。

## 7. view.exe 速查

```bash
# 1. 按名字预览材质（9 槽位，缺的标「缺」）
view --name=w1351_smeh_shandongkou_001.mtl

# 2. 按 hash 预览贴图并导出 PNG
view --hash=4e161e3ccde3c964 --png-out=D:/out

# 3. 模糊按名预览模型
view --name=xianglong_b7

# 4. 预览动画（信封 + Biped 骨架名表）
view --name=w1351_monster_qinhuangjingbingyong_dead.ani

# 5. 列某一类资源（--type 是列表模式，不要和 --name 混用）
view --type=mesh --limit=20

# 6. hex dump 前 N 字节核对结构
view --name=xxx.mesh --dump=64
```

预期输出要点：
- 材质：槽位数量 + 每槽解析结果（解析到的显示路径，缺的标「缺」）。
- 贴图：真实 codec（vs 文件头标签，不符会警告）、尺寸、PNG 路径。
- 模型：信封 tag=mesh v=1；**实测 .mesh 内不嵌贴图名**（40 个样本逐字节核对），
  模型→贴图的接线在 `.mtl` 里，预览 .mtl 即见槽位。
- 动画：信封 tag=ani v=2 备注（如 "Upgraded mtl"）+ bip01 骨架名表。
- 骨骼：.ske 是 JBCF 容器，列出容器内字符串。
