# 运行时挂钩 · 操作手册（第一版，只读）

**前置**：客户端 `D:\TLGL\tlbbgl_x64.exe` **必须已经在跑**（本班按你的规矩不代起进程）。
旁边有 `NEP2_64.dll` / `NEPKernel.sys`（反外挂件）——本脚本只挂 `CreateFileW`/`ReadFile` 并做只读内存扫描，
不写内存、不改指令；若注入被拦，退路是用外部 `ReadProcessMemory` 的只读工具（同一个特征字节清单）。

## 挂上去
```bash
frida-ps | grep -i tlbbgl            # 拿 PID
frida -p <PID> -l D:/TLGL/.scratch/hook/mesh_probe.js -q
```

## 在 REPL 里按顺序取证（对应你说的第 1 步：不预设字段含义）
1. `mods = rpc.exports.modules()` —— 先看模块表（确认引擎模块名，后续按模块下断要靠它）。
2. 让客户端进图/打开一个模型（人或怪都行），REPL 里 `rpc.exports.meshes()` 看它读了哪些 `.mesh`。
3. 用静态切出来的特征字节找副本（客户端即使拷贝过内存，浮点值不会被改写，字节模式应当能命中）：

   | 名字 | 字节 | 说明 |
   | --- | --- | --- |
   | `shou02_row0` | `a5 43 87 be 1a 51 32 3f bc 0b 22 3f` | hubaoshenshou02 拦路段首行前 12B（三个 f32，最独特） |
   | `bird_row0` | `c4 ff b0 45 56 19 fb 45 54 fa e4 44 00 00 00 80` | bird_lf001 首行 16B（末 4B 是 -0.0） |
   | `u92_tail` | `00 00 80 3f 00 00 00 00 00 00 00 00 00 00 00 00 00 00 c8 42 00 00 c8 42 00 00 c8 42` | `1.0` 后接 `100,100,100`——所有 u92 收尾共用，**单用不独特**，要与首行一起判 |

   ```js
   rpc.exports.findBytes('a54387be1a51323fbc0b223f', 8)
   rpc.exports.findBytes('c4ffb0455619fb4554fae44400000080', 8)
   rpc.exports.findBytes('0000803f0000000000000000000000000000c8420000c8420000c842', 8)
   ```
4. 命中地址拿到后：`rpc.exports.refs('<addr>', 16)` —— 看**谁在引用**这一段（这就是「引擎把它当什么」的第一条线索）。
5. `rpc.exports.dump('<addr>', 256)` 把结构摊开，记下前后字段（不猜语义，只记录偏移与取值）。

⚠ 已知局限：若客户端**解压后不保留原字节**（例如解析完就丢弃整段），上面三个模式会 0 命中——
   那就改用第 2 步拿到的读缓冲地址（`meshes()` 返回的 `buf`）当场 dump，并从「读完之后谁改了这段内存」入手。

## 记录规矩
- 每次取证把 REPL 输出**原样**存到 `.scratch/dyn/hook_*.txt`，并写明：客户端版本、进的是哪个场景、哪一份模型。
- 结论只写「观察到了什么」，语义等复现两次以上再写进档案。
