## 1. 产品定位与红线（不可违反）

**产品定位（用户 2026-09-23 最终裁定）**：TLBB 资源浏览器/解包预览器——让不懂格式的美术/策划/开发打开客户端资源，5 秒内知道「这是什么、由什么组成、缺什么、哪些是事实哪些不确定」。

不做：资产知识图谱、考古平台、自动恢复贴图归属（已被数据证明不可能，用户明令停止）。

**铁律（违反即返工）**：
1. **没解出像素就不显示图**——宁可空白/灰卡，绝不拿同目录图顶上
2. **名称一律客户端原文**——不翻译、不编显示名、不给用户看 hash（用户不应接触 hash）
3. **悬空引用显示「缺」+ 说人话的原因**——标准措辞：「客户端只保存名称，没有路径，这是客户端的设计，不是解析失败」
4. **不制造假关系**——错误关联比没有关联更危险；推断只进 relations 不进 refs
5. **只读**——`resources.db` 只读打开，不写任何游戏文件
6. **数据层英文键，中文只在展示层映射**（`kind_zh`/`role_zh`/`tag_zh`）
7. **错误必须说人话**——「Parse Error 0x104857」不合格，「材质槽1 指向 xxx.tga，未找到对应图片，原因：客户端只保存名称」合格

## 4. 格式事实（已验证的二进制布局）

### .mesh（几何，M2-1 刚解出）
```
0x00  64B  版权串 "Copyright 2013-2200 …"
0x40   8B  类型标签 "mesh"
0x48   4B  版本（u32）
0x4C  64B  备注
0x8C   4B  u32 顶点数
0x90   4B  u32 三角面数
0x94   4B  u32 子网格/材质槽数（fwzhongxing 7 材质槽模型此处=7）
0x98…0x117  头部剩余（本批样本全零，未解读）
0x118       位置流  vc×3×f32 连续
            法线    vc×3×f32 ┐ 静态布局（中间段=vc×20 字节）时可解；
            UV      vc×2×f32 ┘ 蒙皮类布局未解时保持空
            [u32 面数] + 面数×3×u16 索引
            …尾部可能有蒙皮/子网格表（trailing_bytes 报告）
```
- **蒙皮类模型**（test_jianzhen 55,864 顶点）：位置流与索引块之间有 ≈22.4B/顶点的**未解中间段**。
  解析器用「先猜静态布局 → 失败则验证式扫描（u32==面数 且其后索引全 < 顶点数）」定位索引块。
- **多子网格模型未解**：fwzhongxing（sm=7）在静态位置起算找不到自洽索引块，尾部索引分块布局待解。
- 实测样本：plane_c01 424B 逐字节闭环（四角 ±0.5、法线 (0,1,0)、UV (0,0)(1,0)(1,1)(0,1)）。

### .mdl（模型定义，2,147 个，type=JBCF）
JBCF 容器（magic `JBCF` v8）。字符串表按序：模型名 → 基目录（以/结尾）→ `.ske` 骨架 → 部件标签（MainBodyMesh/ArmMesh…）+ `.mesh` + `.mtl` 相邻配对 → 挂点/bip* 骨名/tx_* 贴图槽名。**内无 .ani 引用**——动作列表要从资源组 refs 取（`hash→amembers gid→refs kind='.ani'`）。

### .mtl（材质）= JBCF
字符串表即槽位：贴图名/父材质/着色器类。`material_slots()` 现场解析，悬空显示「缺」。
贴图悬空是**类型性**的：`.tga` 名字→实体命中率仅 0.3%，客户端发布时没存贴图路径——工具无错，照实标缺。

### .ani（动作）
信封 tag=ani v=2，备注如 "Upgraded mtl"，内嵌 Biped 骨架名（bip01_* 41 个）。关键帧格式**未解**（M2-4）。

### .ske（骨骼）= JBCF
容器内字符串列出骨架引用与骨名。

### 其它已证事实
- `.mesh` 内不嵌贴图/材质名（40 样本核对）——模型→贴图接线全在 `.mtl`
- PAK 索引 36 字节定长无文件名；贴图名字唯一来源是引擎 JRPC，已穷尽（57,274 条）
- 共享不存在（每成员哈希扇入恒 1）；2.4 万无名贴图是客户端设计（打包时剥离路径）

## 5. 环境与沙箱纪律（**必读，否则浪费几小时**）

1. **Bash 工具全废**（dirname/cd 丢失、路径被改写）——一律用 **PowerShell 工具**；文件操作用 Read/Write/Edit/Grep/Glob。
2. **PowerShell 前台吞 stdout**；`*>` 重定向产出 **UTF-16LE**。抓命令输出：托管 Python `subprocess.run(capture_output=True)` → 写文件 → Read。（`python`: `C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe`）
3. **构建**：`$env:CARGO_TARGET_DIR="D:\TLGL\.scratch\rc3"` + `--jobs 1`；PS 会把 cargo 进度报成 `NativeCommandError`（假警报），**只认 `$LASTEXITCODE`**。
4. **crates/core 没有 anyhow/image 依赖**（离线环境，别加）。
5. **前端改动必须** `node web/build.mjs`（在 `app/` 下跑）→ `cargo build`（dist 编译期嵌入 exe，只改 web/ 不重建看不到变化）。
6. **resources.db 只读**；SQLite 直查用 Python `file:...?mode=ro` URI。
7. **PS 中文输出双重编码成乱码**是显示问题不是数据问题（UTF-16 解开后核对）。
8. **GUI 程序无法从沙箱会话常驻启动**（实测全部失败）：进程被 Job 对象 kill-on-close 连坐（父命令一结束就死）；`CREATE_BREAKAWAY_FROM_JOB` 被拒（WinError 5）；schtasks/reg.exe 在安全黑名单且禁止绕行；PS `Start-Process` 起不来；explorer 代启无效。**让用户自己双击 exe**；验证软件好坏用 CLI 探针（`--probe`，同命令内完成）。判据：脱离 Job 前能活过预热（实测 18s/332MB/warm 1.9s）+ probe RC=0。
9. **子 agent 有频率限制**（2026-09-23 14:33 重置过一次）：429 时别等，改自己动手，或换模型。
10. **前端能验，不用等用户双击**：`.scratch/ui_check/serve.mjs` 是本地 http 自测台——加载 `app/web/dist` 并注入假 `window.__TAURI__`，然后用 browser-use 打开 `http://127.0.0.1:8765/`。**它回放的是 `--probe` 落盘的真实回包**（`stats / page_named / page_unnamed / inspect_<gid> / detail_<gid> / mesh_real / replay` 都放在同目录），不是编的数据；新增视图或新数据路径之前，先在 probe 里把对应回包落盘，否则 stub 会照实报「没有回放这条」。页面左下角有红标，别拿它当预览汇报给用户。
    - **教训**：第一版 stub 只塞了一条名字漂亮的假资产，于是"真实首屏是一墙 16 位编号"完全没验出来——**编的样本只会替设计说好话**。真实回包当场又抓到两个：`what` 把某个 `.tga` 文件名当成资产名；怪物组「图片」区只有一排灰卡，看着像预览坏了。
    - `take_screenshot`：视口内能拍，`fullPage` 报 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`（面板 visibilityState=hidden）。
    - 硬证据用 `evaluate_script`：DOM 断言 + 给 `WebGLRenderingContext.prototype.drawElements` 打补丁后 `readPixels` 数亮像素（3D 是否真画出来就靠这个）。隐藏页 rAF 会被挂起，所以 `MeshViewer.load()` 末尾同步画一帧。

## 6. 多会话协作纪律（本机常有 2+ 个 AI 会话并行）

- **开工前先查文件是否被并发会话占用**：`Get-Item <file> | Select LastWriteTime` 与当前时间对比；几分钟内改过 = 对方正在写，**换文件所有权或转验证角色**（本会话两次靠这个避免撞车）。
- **同一文件多处编辑禁止放在同一条消息**（读旧写回互相覆盖）；并行 agent 按文件所有权隔离。
- **两会话共用 `rc3` target 目录会撞 exe 锁**（"拒绝访问 os error 5" 假红，补跑即绿）——最好错开 CARGO_TARGET_DIR，或等对方构建完再跑。
