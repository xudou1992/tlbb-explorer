### 2.1 Agent A：复合数学层 ✅ 完整交付

**文件**：`crates/core/src/preview/pose.rs`（新，23.6KB）+
`crates/core/tests/pose_compose.rs`（新，4 条闸门）+ `mod.rs` 一行注册。

**公开 API**（std only，行主序 4×4、行向量约定，`world = local · parent_world`）：
`mat_identity / mat_mul / quat_to_mat / trs_matrix / mat_inverse_affine`、
`bind_worlds(&SkeletonHierarchy)`、`pose_frame(&h, &Anim, frame)`、
`skin_palette(&h, bind, world)`、`posed_vertices(&h, palette, &nodes, &positions)`。

**三个口径决定（都有数字，不是拍的）**：
1. **存储 bind 矩阵就是世界空间 bind**——当局部沿链复合与存储值逐元素差
   1.0~3.8（30 根带矩阵骨全超 1.0），局部口径被数字否掉。
2. 四元数分量序取 **(x,y,z,w)**（D3DX 惯例；未从字节钉死。旁证：按
   (w,x,y,z) 组合 idle01 整副骨架塌成平面，(x,y,z,w) 水平走向与网格一致）。
3. 蒙皮权重**不归一**（Σw<1 照原样加权）、未覆盖顶点原样、对不上回 None。

**闸门实测**：档案骨距 3 对逐对命中（1.0991 / 0.4052 / 0.5460，容差 1e-3）；
bind 恒等式 |v'−v| ≤ 1.33e-7；15 条动作 × 555 帧 × 46 骨 = 25,530 张矩阵
全有限无 NaN。

**没解决、已如实记档的开口（这就是播放姿势还怪的原因）**：
- 存储 bind 骨架与网格不重合：骨平移 y∈−0.16..0.78，网格立在 y 0.019..2.240
  （偏 1.84）；尾部 `top` 矩阵平移 (0, **2.3455**, 0) 像 `000` 根的定位，
  但 `top→000` 挂接未实证。
- `.ani` 静态区 +48 首条与存储 pelvis 平移是**定轴轮换**关系——两容器的
  轴系标注 unresolved，与 64B 局部矩阵、88B 对角块两个老开口同源。
- 因此蒙皮位移统计偏大（idle01 帧均值 1.41~1.46、最大 2.37）：**闸门只钉
  「不 panic 且无 NaN」，没硬凑口径**。换 bind 口径（top 定位/轴系轮换）
  属于新解，须先在 .scratch 立证据再动代码。

### 2.2 Agent C：hamigua 尾部变体 ✅ 解穿并落码（本班最大增量）

**文件**：`geometry.rs::parse_hierarchy` 加法改动（三处：变体起点、
挂点数=0、影响表判据）+ `tests/hamigua_tail.rs`（5 条，含 2 条反向验红）+
档案 `.scratch/hamigua_尾部变体_20261005.md`（hex 现场齐全）+
脚本 `.scratch/hamigua_*.py` + 全名单 `.scratch/hamigua_v2_family.txt`。

**解穿的文法**（同一条目语法的三个开关，不是新文法）：
1. 无 origin/top 前奏：尾部直接 `[u32 -1][名字×2]` 起步（-1 = 根标志位）；
2. 挂点数可为 0：收在 `[u32 1][u32 0]`（旧实现 count==0 → None，误杀）；
3. **影响顶点表按「绘制序」存**（`1,0,2,3,…,65,64`，互异且 <顶点数，
   不是严格递增——旧判据拒了它，这是最大的一把）。

**数字**：declared>0 的 2,696 份 .mesh 走通数 1,439 → **2,208**（V0⊆V1⊆V2
逐文件验证、回退 0）；族定义按尾部结构=**1,104 份**；变体族 ≥14 骨且
bip01 命名的 315 份做 11 条 Biped 关系抽验 **97.5% 命中 ≥8 条**。
上午档案两处旧描述已修正（末条目其实有名；「多出的 64B 块」就是已知开口那个 64B）。

**剩余 488 份失败的族群分布**（待办在这）：tx-not-eof 128（挂点段后还有
~116B 尾巴）+ no-candidate 171（无 origin 也无 [-1][名字×2] 起步）+
stuck 171（疑似第 4 种块型）+ 多根 17（`b_bone_*` 族）+ 孩子列两次 1。
另有 5,300 份 declared=0 的静态景，None 是正确行为不用管。

## 6. 环境与操作纪律（Windows 沙箱，踩过的坑都在这）

- 构建/测试**必须**：`CARGO_TARGET_DIR=D:/TLGL/.scratch/rc3` + `--jobs 1`
  （不带 target-dir 会写到另一处 target，跑的 exe 是旧的——「改好了」是假的；
  多 agent 共享 rc3 靠 cargo 锁排队，不许换目录不许调 jobs）。
- PowerShell 是抓输出主力但：控制台 cp936 会把中文打成乱码、`*>` 产出
  UTF-16LE——**结果一律写进文件再读**；判断成功只看 `$LASTEXITCODE`。
  Git Bash 可用但路径一律正斜杠。
- **离线环境**：crates/core 不许引新依赖（std only；serde_json 已有可用）。
- 前端测试 `cd tlbb-explorer/app && npm test`（264 条，别用裸
  `node --test tests/`，Node 25 下 MODULE_NOT_FOUND）。
- CLI 全链自检：`./tlbb-shell --probe 曹霜`；地图金标准：
  `node tools/map_golden.mjs`（动过 scene/几何解析必跑）。
- `resources.db` 一律只读；真实模型字节样本可用
  `cargo run --offline --example dump_raw` 或 mesh2glb 现成管道取。
