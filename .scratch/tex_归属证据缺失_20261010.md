# 贴图归属证据核查——UV 试贴没有标准答案可对（2026-10-10）

## 为什么要查这一步

交接报告 §4 第 3 条要求「把 unknown 815 按失败原因分桶」，桶已经分完并提交
（`stats.unknownSplit` = noUv 442 / degenerate 263 / noCandidateScore 8 / lowSignal 102，
另 `tryableByUv` 2,105）。分完桶要回答下一题：**该修度量，还是该换证据？**
判据只有一个——拿客户端自己声明的贴图当标准答案，量 UV 度量把它排到第几（召回率）。
这一份记录就是那次测量的结果，结论是**这条答案链在现有数据里不存在**，六条桥全部证伪。

## 六条桥怎么断的

1. **refs.to_hash**——`.tga` 30,585 条只有 25 条落 hash，剩下全悬空（`dangling` 表 14,377 个名字）。
2. **resources.name 反查**——点名的名字能查到的行全是小尺寸 WEBP，与候选池零交集。
3. **filecrc 桥**——同名内容 CRC 自连接 0 命中。
4. **资产组桥**——`amembers` 里贴图成员 0 个匿名，`assets.primary_hash` 也 0 个。
5. **path_hash 桥**——`jpak::crypto::path_hash` 本身验准：库里有路径的 4,000 行**全中 4,000**。
   但拿 mtl 所在目录 + 点名文件名拼 1,500 种写法（裸名 / `resource/` / `data/` / `source/` / 同目录）
   命中库里 **0**。说明匿名 hash 不是这批路径的 path_hash，至少不是任何我猜得出的拼法。
   （`.scratch/tex_pathhash_bridge.py`、`.scratch/tex_pathspell_probe.py`）
6. **字节里扫 hash**——从解出来的 39,348 份 mtl/mdl/mesh/ske/pu/ani 里随机抽 400 份共 14.9 MB，
   8 种对齐逐个 8 字节窗口比对匿名贴图 hash 集合，命中文件 **0**。（`.scratch/tex_bytescan_hash.py`）

## 结论

- **召回率测不出来**：不是 UV 度量差，是**现有数据里没有任何一条边能把「模型」和「它该用的那张匿名贴图」连起来**。
  所以「该修度量还是该换证据」这一题的答案是**换证据**，而“阈值/退化带/兜底层次”这些参数
  在没有标注的情况下**不可能自动校准**——它们调的是排序，而排序对不对无参照。
- 界面口径没吹牛，不用改：`app/web/lib/textureState.js:8` 已写明
  「候选分数是 uvfit 的 UV 岛内外方差比——特征指标，不是归属概率」，第 119 行的 basis 同样只在有排名时说综合分。
- **目前唯一的标签来源是人工确认**（`0d8107e` 的覆盖贴图机制）。于是贴图线的下一步不是调参，
  而是**把人工标注做快**：候选组一次只铺第一组（`detail.js` 取 `[0]`）就是最直接的吞吐瓶颈。
- 另一条能一次性拿到成千上万真答案的路是**运行时挂钩**：引擎给某个模型绑定时请求的贴图身份，
  抓一次就是一批标准答案。这条要起客户端，按规矩得先问用户，且需要一次实机操作。

## 顺带记下的一个疑点

2,818 份模型 × 前 10 槽位里只出现了 **419** 张不同的贴图。也就是说度量的冠军高度集中在少数几张大图上，
这与「岛内外方差比」对大图/高方差图天然偏高的性质一致——在拿到真标签之前，
这个集中度既可能是「确实少数几张通用贴图」，也可能是度量本身的退化，**不要拿它当结论**。

## 榜的区分度量出来了（不需要标注就能算）——界面已加上这一句

按**界面看到的顺序**（综合分降序，与 `texture_override::rank` 同规则）数全库 2,368 份有榜的模型：

```text
榜首去重后只有 147 张贴图
  第 1 名 dae002f82c686d00 当了 260 只模型的榜首
  出现 ≥50 次的只有 12 张，这 12 张合计覆盖了 1,078 只模型的榜首（46%）
  另有 325 只模型的榜首「岛外方差 = 0」（无对比，上一节那个标记）
```

**这就是「贴图呢」的真实原因之一**：榜看着是十张卡，实际是同一批通用图在不同模型上反复夺冠——
人没法从榜首看出「这是为这只模型挑的」还是「这张在哪儿都第一」。

**已落地的处理**（不需要任何标注，纯事实）：候选卡上新增一行
「这张在 N 只模型的榜首出现过」，N ≥ 50 才追加「——它对这只模型说明得很少」。
少量重复（3 只、12 只）只报数不劝退：通用纹样被多只模型用到是正常的，不许把正常说成可疑。
N 由后端 `scan_first_places` 现扫批量缓存得出，**口径与 `rank()` 一致**（有闸门测这条：
`first_place_counts_follow_the_ui_ranking_not_cache_order`——按方差比顺序数就是错的）。

**两条我自己说错、当场撤回的**：① 我先说「榜首集中 = 471 只」，那是按**缓存里的方差比顺序**数的，
界面看到的榜会重排，正确数是 260；② 我先说「度量偏黑」，实测各名次平均亮度 33.7~41.2、
中位全是 24，**排名与亮度不相关，这条不成立**。
