# 地图 GUI 验收 · 2026-09-26

收的是 V0.2 第一个收口项：**地图浮层从没对着真实回包跑过一次**。
之前只有 `--map` 无窗口计数和 110 条单元测试，界面那半边是空的。

## 怎么验的

不给界面喂手写的假回包——加了一条无窗口出口，把**界面点进去那条链的原始返回值**直接落盘：

```
tlbb-shell --maps                      → .scratch/ui_check/map_list.json
tlbb-shell --maps <图ID> [<图ID>…]     → .scratch/ui_check/map_scene_<图ID>.json
```

`--maps` 走的就是 `map_view::list_of` / `map_view::scene_of`，也就是 `map_list` /
`map_scene` 两个命令本体（命令层已抽成薄壳，不再有两份实现）。
自测台 `.scratch/ui_check/stub.js` 只回放这些文件，没落盘的图一律报错，不拿别的图凑。

取证方式：`browser-use` 打开自测台 → 点顶栏「地图」→ 逐张点行 →
断言 `#mapBanner` / `#mapInfo` / `#mapAbs` / `#mapMiss` 的文本与回包字段逐一对齐，
并在**应用自己的 `gl.drawElements` 调用之后**立刻 `readPixels`（不改生产代码，钩在
`canvas.getContext` 上）。这样"亮像素"只能是那条链真画出来的。

## 逮到的三个真问题（都已改）

1. **`w1351_fb_jiebai_001` 被界面说成「一个都没摆东西」。** 它唯一一个 `.scene` 是版权头
   容器（`1751607666` = "jule"），根本没交出记录。「没摆东西」和「读不通」是两件事。
2. **`mqts_empty_001` 被说成「一条都没对上模型文件」。** 那 2 条记录摆的是 `.mdl`，
   文件在客户端里真实存在——这不是"没对上"，是"本来就不是网格"。
3. **控制台每条 WebGL 警告**：`uniform1f: location is not from the associated program`
   （`mesh-viewer.js:297`）。`trackAllocation()` 在第一帧之前设 `uUseInst`，那一刻没有
   current program，这句是**静默空操作**——注释里写的"不会被谁挡住"其实根本没生效。
   现在 `useInstanced` 先 `useProgram`，警告消失，大理那张图重新验过像素没退化。

①②收进 `web/lib/wording.js:mapNoObjects()`（纯函数），`tests/wording.test.js` 用上面
三张图的真实数字钉住五种分支；`map.js` 顺带删掉一个从没用了的 `pctText` 导入。
前端测试 **115 / 115 绿**（原 110 + 新 5）。
