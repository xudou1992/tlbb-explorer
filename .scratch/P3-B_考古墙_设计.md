# P3-B 图片考古墙 · 设计

> 目标一句话：让 24,261 张没名字的图 **能看、能分组、能打标签**。
> 不恢复原名，不猜模型归属。

## 为什么是「墙」而不是「恢复」

上一轮（P3-B-0）已经把名字来源查死了：
PAK 索引无字符串槽位、JMT1 头无文件名、`ResourcePath.cfg` 只覆盖 `ui/`。
⇒ 官方打包时就没放名字，**不是解析器漏了**。

内容特征测量结论（1,619,100 对）：
- 全对全均值 31.60（≈随机上界 32）→ 全局互不相关
- 最近邻中位 14 / P10 0 → 每张图确实有更像的伙伴
- 孪生率 30.4% / 同族率 69.8% ⇒ **半自动归类**

所以出路是：**内容聚族 + 人工命名**，不是自动归属。

## 三层结构

```
layer 1  「一眼看全」      24,261 张缩略图排成墙，能滚、能搜、能筛
layer 2  「按族看」        自动聚出的族并排摆，族内相似度高、族间低
layer 3  「打标签」        人看着图打中文标签，标签落盘成资产知识
```

## 数据契约（唯一真相：SQLite，Rust 只读）

新增三张表，全部由构建脚本写入，Rust 端只读消费：

### `wall_tex` — 每张无名贴图的墙体记录
| 列 | 含义 |
|---|---|
| `hash` | 资源哈希（主键，接 `resources.hash`） |
| `dhash` | 64 位 dHash，**存成 16 位十六进制字符串**（SQLite 无 u64） |
| `mean_r/g/b/a` | 平均色，用来判退化和做色系筛选 |
| `lum_sd` | 亮度标准差，<3 视为近似纯色（dHash 无意义） |
| `edge` | 边缘能量：判「是不是有内容」 |
| `alpha_cov` | 非透明像素占比：判「是不是透明蒙版」 |
| `thumb` | 缩略图文件名（相对 `wall3/thumb/`） |
| `decoded` | 1=解出像素；0=解不出（**绝不拿别的图顶替**） |
| `fail_reason` | 解不出时的原文原因 |

### `wall_group` — 自动聚出的族
| 列 | 含义 |
|---|---|
| `gid` | 族号 |
| `rep_hash` | 代表图（族内到其他成员距离和最小） |
| `n` | 成员数 |
| `dia` | 族内最大距离（直径），衡量族紧不紧 |
| `mean_d` | 族内平均距离 |
| `codec`/`w`/`h` | 族的主尺寸（多数表决，仅作展示参考） |

### `wall_member` — 族成员
| 列 | 含义 |
|---|---|
| `gid` | 族号 |
| `hash` | 成员 |
| `d_rep` | 到代表图的距离 |

### 人工标签（人写的，只增不改）
### `wall_tag`
| 列 | 含义 |
|---|---|
| `gid` | 族号（**标签打在族上，不是单张图**——因为人认的是"这一堆"） |
| `label` | 中文标签，如「峨眉装备」 |
| `note` | 备注 |
| `at` | 时间戳 |

标签打在族上是有意的：人看一排图说"这是峨眉装备"，说的是这一堆，不是某一张。
单张图的标签应该由族继承，避免 24,261 个标签要人手工敲。

## 聚类算法

```
1. 把 24,260 张按 dHash 装进 64 位桶
2. 分段预筛（LSH）：32 段 × 2 位，**任意一段完全相同**才进候选
   正确性依赖 SEGMENTS(32) > KIN(16) ⇒ 距离 ≤16 的对至少有 16 段相同，必然被捞到
   ⚠ 早先用 8 段是错的：16 位差异可以铺满 8 段，真孪生会被静默丢掉
   已在 wall3_cluster_selftest.py 里对穷举验证一致（含最恶劣情形）
3. 候选对建并查集，路径压缩
4. 连通分量 = 族
5. 族内挑代表（到其他成员距离和最小）
6. 族超过 400 张时按更严阈值再切
```

阈值来自标定：**≤8 孪生，≤16 同族，>24 无关**。

### 实际结果（24,260 张）

| 项 | 数 |
|---|---|
| 候选对 | 149,182（对全对全 294,261,670 省掉 99.95%） |
| 孪生对（≤8） | 16,657 |
| 连通分量 | 14,461 → 切开后 **20,743 个族** |
| **真分出组的族** | **1,515 个，覆盖 5,032 张** |
| **孤图** | **19,228 张（79.3%）** |
| 最大族 | 403 张（族 0，混族） |

⚠ **口径提醒**：孤图**不是** `fam < 0`——聚族给每一张图都分配了族号，
找不到伙伴的也各成一个单成员族，所以 `fam` 恒 ≥ 0。
判孤图要看 `wall_family.n == 1`。同理报"族数"时要分开说，
否则 20,743 这个数字会让人误以为分出了两万个组。

### ⚠ 缩略图为什么不在工程盘

本机沙箱对「在已有目录里新建文件」做了拦截，实测：

| 目录 | 单个 7.4 KB 文件 |
|---|---|
| `D:\TLGL\.scratch` | 33.6 ms |
| `D:\TLGL` / `D:\` / `C:\Users\Administrator` | 20.7 ~ 21.0 ms |
| **`AppData\Local\Temp`** | **0.22 ms** |

差约 **100 倍**。同一个二进制：不开缩略图 **7,647 张/秒**，开缩略图 **21 张/秒**。
把缩略图挪到 TEMP 后全库收料 **604s → 5.9s**。

所以 `wall_harvest` 有 `--thumb-out`，`wall3_page.py` 有 `--thumb-rel`
（生成 `file:///C:/.../tlbb_wall_thumbs/` 前缀）。
`raw.tsv` 只有几 MB、单文件，留在工程盘没问题。

**注意：跨卷 `move` 比重算更慢**（复制+删除，且触发沙箱删除保护）——直接重新生成。

**为什么缩略图独立目录、标签独立库**：
`resources.db` 是「客户端事实层」，只读、可重建、可校验。
缩略图和人工标签是「理解层产物」，会反复重算和人工编辑。
混在一起会破坏"只读事实层"这条铁律。

## 铁律（继承）

1. **没解出像素就不显示图** — 灰卡 + 失败原因，绝不拿同尺寸图顶替
2. **不编名字** — 墙上只有 hash / 尺寸 / 编码，人打的标签单独标注"人工"
3. **不猜归属** — 不出现「这个属于曹霜」这种没依据的断言
4. **只读游戏文件** — 不写任何 `.pak`，不写 `resources.db`
