# 分层贴图的排序证据普查（2026-10-27）

目的：把「第 i 段子网格 ↔ 第 i 条材质贴图」从**按 `.mtl` 顺序猜**升级成**有编号可核**。
工具：`crates/core/examples/mtl_segment_census.rs`（只读 db/pak，不落任何资源字节）。

```text
cargo run --offline --example mtl_segment_census -- --limit 1200 --show 5
```

样本口径：清单里 `.mtl` 能找到**同名茎 `.mesh`** 的 1,200 份（跳过 2,080 份没同名网格的
共享模板材质）。取字节失败 0 份。

## 结果（分母都是 1,200）

| 口径 | 成立份数 |
|---|---|
| 材质段数 == 子网格段数 | **259 / 1,200** |
| 颜色贴图数（去 `_pbr`、去 `mask`）== 子网格段数 | **1,069 / 1,200** |
| 颜色层数 == 段数 且 含 `effect_add_trans` | 9 / 23 |
| 颜色层数 == 段数 且 不含 effect 材质 | 1,060 / 1,177 |
| 非 pbr 贴图数 == 段数 | 1,065 / 1,200 |
| 段里出现过 `mask` | 17 段 / 共 20 张遮罩，其中「遮罩后紧跟非遮罩」12 张 |
| 着色器名里带 `add`/`trans` | **0 / 1,200**（全是 `dynmodelshader` / `newsfxshader`） |

字符串表角色顺序（M=材质 T=颜色 P=pbr K=遮罩 S=着色器）：`TMS` **907**、`MTS` **152**、
`MS` 81、`TMST` 8、`MTSMTT` 8、`MTPTS` 6、`MTSMKT` 6 ……（前 15 种占绝大多数）。

## 推翻的两条假设

1. **「材质名起段，段内贴图归它」不成立**：907/1,200 份是 `贴图 → 材质 → 着色器`，
   贴图排在它自己的材质名**前面**；按「材质名起段」会把贴图配给上一条材质。
   ⇒ 改成「每条贴图认领**位置最近**的材质名」，两种顺序都成立（单测钉住）。
2. **「材质段数 == 子网格数」不能当判据**：只有 259/1,200。段数还受共享模板材质
   （`template_default_npc`、`template_sfx` ……）影响。

## 立的四条规则（都已写进 `texture_override.rs` 单测）

1. `_pbr` 永远是通道图，不成层。
2. 一条颜色图是不是叠加，看**离它最近的材质名**里有没有 `add`（着色器名 0/1,200 带；
   全库只有 `template_default_effect_add_trans` 这类 23/1,200 是叠加材质）。
3. 叠加材质里「多张颜色图、都没遮罩」的第一张按**不透明**画：12 例这种组合里，第一张
   **12/12** 只在单个模型出现（模型自己的花纹/旗面），后续 **11/12** 是跨模型共用图
   （`texture_lf012` 出现在 10 个模型）⇒ 后者才是光效。照叠加画，旗子/卷轴整片透明。
4. 对齐证据只认**颜色贴图数 == 子网格段数**：成立就写「一张对一段」，不成立就在界面
   写「先后对应未验证」，并把两个数摆出来。遮罩配不上颜色层的张数也如实报。

## 不对齐的 131 份拆桶（2026-10-27 第二轮）

```text
不对齐 131/1200：
  颜色少于段 106 —— 其中完全没有颜色图 87（零贴图 82、只有 pbr 5）、多材质 20、有重名图 0
  颜色多于段  25 —— 多材质 20、有重名图 0
```

- **87 份是「材质表里没有颜色图」**：82 份一张贴图都没有（`w1351_an_model_wave_h001`：
  材质只有 `template_default.mtl` + `DynModelShader`），5 份只有 pbr（`template_pbr_water` 一类）。
  这类颜色由客户端着色器算 ⇒ 界面现在返回**说明性空计划**（不是报错、也不再拿候选榜乱试贴）：
  「材质表里没有任何贴图（只有材质模板 + 着色器），颜色由客户端着色器算，预览器复现不了 ⇒ 保持灰模」。
- **19 份「颜色少但不为零」**：一张图铺多段（基础层跨段），界面标题会报段跨度。
- **25 份「颜色多于段」**：多出来的叠在基础段上（强制叠加）。样例 `w1351_model_bell_h002.mtl`
  段=2 颜色=2 子网格=1，第二张是 `em_0415.dds`（**emissive 发光图**）⇒ 按叠加画正是发光该有的画法，
  这条规则在这里得到旁证。
- 真正「既没有解释、也没有界面对齐证据」的只剩这 44/1,200（3.7%）。

## 落到界面

- 立体模型下方一排筹码：`全部` / `基础 第 1 段` / `特效 1 第 2 段` / `材质 2 第 3 段`……
  点一层只画那层，用来核「这层说的第几段」有没有配错。
- 标题里直接带「颜色 5 张 = 子网格 5 段」或「颜色 3 张 ≠ 子网格 2 段（顺序未验证）」。
- 换网格/空资产时筹码立即收掉（真窗口实测过旧筹码会赖在没有网格的资产上）。

## 「颜色少于段数」的旁证：UV 岛是否互不重叠（2026-10-27，`crates/core/examples/submesh_uv_share.rs`）

口径：对「颜色贴图数 < 子网格段数」的份，按后端同款规则算出基础层要铺哪几段，
再给每段单独建一张 256×256 的 UV 覆盖图（`preview::build_mask`），量「第 0 段 vs 其余共用段」的重叠。

样本 4,000 行 `.mtl` 里筛出 **187 份**符合形状：

```text
UV 几乎不重叠（<1%）  121 / 187   ← 各段落在同一张图的不同区域，图集式共用，支持「基础层铺多段」
轻度重叠（1~25%）       8
重叠 ≥25%              58（其中多数是 100%：几段 UV 完全同区）
```

- 121/187（64.7%）有正旁证：同图不同区，基础层铺多段站得住。
- 重叠大的那 58 份**不改画法**：材质表本身就只给了那几张颜色，客户端也没有别的可绑
  ⇒ 画法一致，只是「为什么这么铺」说不清，界面照旧写未验证。
- 界面话术据此改成**说清原因**（不再是笼统的「≠」）：
  `颜色 3 张 < 子网格 6 段（其余 3 段按基础层铺）` / `颜色 2 张 > 子网格 1 段（多出的 1 张叠在基础段上）`
  / `颜色 5 张 = 子网格 5 段`；三形状在 gid 1739 / 8 / 1670 真窗口核过。
