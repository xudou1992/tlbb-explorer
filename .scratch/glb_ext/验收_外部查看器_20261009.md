# 外部查看器验收：three.js 实放 HEAD 导出的 rigged GLB（2026-10-09）

交接报告 §4 第 1 条、README「人眼验收欠账」里那句「另丢一份 .glb 进 Blender 或
three.js 播动画」——本班做掉了 three.js 这一半（本机没有 Blender）。

**灯号：导出 🟢 / 「不再撕」这条口径 🔴。**
导出在业界实现里站得住：8/8 份第 0 帧精确。但**非锚帧按边长量仍然撕**，
而且 app 自己的蒙皮路径量出来是同一串数字——问题不在导出器，在播放锚口径本身。

---

## 一、做法（全部可复算）

- 样品：用 **HEAD 现编的** `mesh2glb --rigged` 导，不吃 10-06/10-07 的旧产物。
  `CARGO_TARGET_DIR=.scratch/rc3 cargo build --release --bin mesh2glb`，
  样木树 `.scratch/glb_ext/tree/`（5 个组目录从 `.scratch/out/tree` 拷来，
  保留 `data/source/npc/quest/…` 相对路径，`ani/` 在同组目录里）。
  **8 份网格 8 份 glb，fail=0**，顶点 6,766：西域窃贼 yifu+shoutao、
  蛛帅 yifu、王若语 yifu+shoutao+lian、猫咪 b6、灵羊。
- 查看台：`.scratch/glb_ext/view.html`——three.js **0.169**（`web-viewer/node_modules`）
  的 `GLTFLoader` + `AnimationMixer`，蒙皮与包围盒一律走 three 自己的实现
  （`SkinnedMesh.getVertexPosition` / `computeBoundingBox`，CPU 路径与 GPU 同一套码）。
  **不加任何 rebind 补丁**：外部实现按 glTF 规范自己算，才算验收。
- 驱动：`.scratch/glb_ext/verify.mjs`（逐份逐动作逐帧）、`stretch.mjs`（边长）、
  `interp_probe.mjs`（关键帧 vs 帧中点）、`report.mjs`（逐顶点/逐骨）。
  本机 headless Chrome + CDP（`--remote-debugging-port=9227`，自己的 user-data-dir），
  页面 `http://127.0.0.1:8765`。
- app 侧对照：`crates/core/src/bin/stretch_probe.rs`——同一把尺（三角形边长倍数）
  量 `pose::skin_palette` + `posed_vertices` 的产物，一次比三种锚。

## 二、判据与结果

### 1. 第 0 帧精确（导出侧成立）🟢

8/8 份、每份 4 条动作，**动画第 0 帧的蒙皮包围盒 == 不播动画时的 bind 包围盒**：
`grow 1.0000 / drift 0.0000`，且**被拉长的边 0 条**（2,538 条边全查）。
重定基（`W' = B·A⁻¹·W`）在外部实现里逐骨逐顶点复现了 app 的 frame0 恒等式。

⚠ 这条**不能当「不撕」的证据**：frame0 恒等对任何权重装法都成立
（`B·A⁻¹·A·B⁻¹ = I`，与顶点挂在哪根骨无关），它只证明骨架树 + IBM + 通道对齐了。

### 2. 非锚帧按边长量仍然撕 🔴

顶点位移判不了撕不撕——正常摆动也会把顶点搬走。**同一个面上的相邻顶点被拉开
距离**才是撕。逐三角形三条边各量一次 bind 长度 vs 这一帧长度：

主样本 `w1351_monster_xiyuqiezei_yifu_001`（781 顶点 / 846 面 / 46 骨 / 2,538 条边）：

| 动作 | 时刻 | three.js 超 1.5 倍 / 超 2 倍 / 最大 | app 同帧同尺 |
|---|---|---|---|
| idle01 | 第 0 帧 | 0 / 0 / 1.00 | 0 / 0 / 1.00 |
| idle01 | 0.175（帧 5） | 161 / 23 / 4.17 | 101 / 6 / 3.08（帧 5） |
| idle01 | 0.35（帧 10） | 260 / 91 / 4.92 | 265 / 91 / 5.20 |
| idle01 | 0.525（帧 20） | 351 / 200 / 6.67 | 331 / 191 / 6.69 |
| idle01 | 0.7（帧 25） | 346 / 215 / 6.38 | 375 / 242 / 6.57 |
| idle01 | 0.875（帧 35） | 146 / 44 / 3.12 | 146 / 44 / 3.12 |
| walk | 0.15（帧 6） | **445 / 246 / 24.09** | **445 / 246 / 24.09** |
| walk | 0.3（帧 12） | 399 / 304 / 14.34 | 399 / 304 / 14.34 |
| walk | 0.45（帧 18） | 308 / 200 / 16.76 | 308 / 200 / 16.76 |
| walk | 0.6（帧 24） | 366 / 219 / 13.77 | 366 / 219 / 13.77 |
| walk | 末帧 | 0 / 0 / 1.00 | 0 / 0 / 1.00 |

（idle01 两边数字有小差，是 three 的插值取值与整数帧取值差半格；同一时刻
`0.875 = 帧 35` 两边一字不差。walk 四行完全相同。）

**画面**（`.scratch/glb_ext/shots/`，`--only=xiyuqiezei_yifu --shots` 生成）：
`a_rest_*` 完整站立的人（含弯刀），`b_bones_*` SkeletonHelper 叠在身体里的骨架树，
`c_idle_mid_*` / `d_walk_side_*` / `e_run_peak_*` 同一份文件播到中途：躯干在、
四肢与上身皮肤被拉成巨大的薄片——**这就是上面 4~24 倍的边**。

### 3. app 与导出是同一件事（撕不在导出器）

`stretch_probe` 三种锚同尺对比（主样本 idle01）：

```
帧 | frame0 锚(现口径) | bind 锚 | bind 锚+静态区补位   （超1.5 / 超2 / 最大）
 0 | 0/0/1.00          | 487/418/28.15 | 487/418/28.15
20 | 331/191/6.69      | 481/414/27.49 | 481/414/27.49
```

- **bind 锚更糟**：每一帧（含第 0 帧）都是 480 条边超 1.5 倍、最大 27~28 倍，
  且不随帧变化——与 10-07「裸 bind 锚 15/15 不能播」同向，只是这次的尺更硬。
- **frame0 锚比 bind 锚好一个量级，但仍然撕**：10-07 那句「frame0 锚 15/15 全胜」
  成立，「不撕」是按**帧均位移**（0.22/0.85）说的，换到边长口径就不成立了。

## 三、排除项（别再回去试）

1. **不是插值/四元数反号**：`interp_probe` 把 walk 的 16 个关键帧时刻与 15 个帧中点
   分开量——关键帧上 grow 最大 **1.6383**，帧中点 **1.636**，同一量级。
   落在导出值本身上，不是帧之间算坏。
2. **不是无记录骨的 bind 占位**：用 `rest.rs` 反解出的位置补上 15/16 根无 96B
   记录骨的平移，三种锚里 bind 与 bind+补位**逐帧一字不差**。原因很直接：
   **没有 96B 记录的骨也没有影响顶点表**，调色板里它们的条目根本不被任何顶点消费，
   补位只改骨线显示，改不了蒙皮。
3. **「差额挂根」策略只解释一小半**：主样本 781 顶点里 252 个是全权重挂根骨的
   （无影响表 → `unify_weights` 把差额挂根）。被拉开的边按两端是否挂根分：
   walk 帧 6 的 445 条里 **305 条两端都有正常权重**、140 条一端挂根；
   idle01 帧 20 的 351 条里 210 条两端正常、141 条一端挂根。
   **挂根要改（根骨带根运动，挂它的顶点会整块滑开），但它不是主因。**
4. **不是导出器与 app 分叉**：见上表同帧同数字。10-07 记的「规范侧对账 7.15e-7」
   是真的，只是那条对账比的是「两边算得一样」，不是「算出来不撕」。

## 四、下一刀（按性价比）

1. **撕的判据要先立住**：把边长口径写成闸门（`stretch_probe` 已有函数，
   落 `crates/core/tests/` 一条：主样本 idle01/walk 逐帧超 2 倍边数必须有上界），
   否则任何「不撕」的结论都可以被位移口径反复解释。
2. **主因指向 `.ani` 与 `.mesh` 两套骨架的映射**，不是权重也不是导出：
   frame0 锚把误差压到 6.7 倍（bind 锚 28 倍）说明 `.ani` 内部连贯、
   与 `.mesh` 差一个**逐骨不一致**的变换——10-06「不唯一」否掉全局 R、
   10-09 否掉「补 bind 占位」，剩下的口子是 exe 侧动画求值函数
   （`EsSkeleton` 构造 `sub_14073F7A0`，既定方针要 IDA 会话）。
3. **挂根策略单开一条**：无影响表的顶点应当**留在 bind 原位**（权重挂一根
   自身不调的骨，或导出时把它们的权重和记为 0 并在查看器侧不动），
   而不是挂带根运动的根骨。这条能消掉 30~40% 的撕边，可测。
4. Blender 那一半仍欠：本机没装，需要用户配合或装一个。
