# 父骨链验证 · 2026-10-05 · 🟢 解出

**结论先行：父骨链解出了。** 它不在任何单个字段里，而是 `.mesh` 尾部每个条目的
**孩子名单**：`[块]* [u32 标志][名字×2][u32 孩子数][孩子数 × 孩子]`。
孩子槽要么是 32B 名字（无绑定矩阵的骨），要么是整条 96B 记录（有矩阵的骨，
名字段就是孩子名——共用字节）。把全部条目的孩子名单收起来，除根外每个骨
恰好被列一次，父子挂接就齐了。已写进 `crates/core/src/preview/geometry.rs::parse_hierarchy`
并带 6 条闸门测试（`crates/core/tests/bone_hierarchy.rs`，全绿）。

样本：`D:\TLGL\.scratch\ani\w1351_monster_xiyuqiezei_yifu_001.mesh`（52,536B，
0x110 声明 46 骨，尾部起点 0x7690）。脚本：`.scratch\parent_tail_dump.py`、
`parent_names2_scan.py`、`parent_walk.py`、`parent_diff.py`（差分）。

## 步骤 1：变长索引表的长度字段 —— 🟢 解出（但它是蒙皮，不是父骨）

把 36 条 96B 记录之间的 gap 全量按 u32/f32 排出来（`parent_tail_dump.txt`），
主文档里那条「`[u32 头][u32 0][u32 索引×N]`」的真身是：

```text
[u32 N][N × u32 顶点号（严格递增）][N × f32 权重]     ← 影响顶点表（蒙皮）
```

实测（bip01_spine 条目，gap 起点 0x7b04）：头 = 71，接着 71 个顶点号
0,1,2,3,6,11,…,776,777（全部 < 顶点数 781 —— 0x110 之外 0x8C 处的 u32 才是顶点数），
再接 71 个权重 0.1,0.1,0.37,…。到下一条 96B 记录的距离 = 8 + 8N +
后面的块，对账分毫不差。**头的 u32 = 元素数 N，不是字节数**；「u32 0」其实是
顶点号 0。这与 `geometry.rs::read_skin` 已钉住的口径一致，差分确认值域
随顶点数走、与骨数无关（spine 表最大 777 < 781 顶点；骨数才 46）。
`bone11` 条目（gap 196B）：`[4][253,256,647,648][0.5,0.3052,0.5,0.3052]`，4+16+16=36 ✓。

## 步骤 2：两份不同骨数的 .mesh 差分 —— 🟢 语法全库成立

把差分扩成 681 份抽样（按声明骨数分桶，1~249 共 155 种骨数），
`parent_diff.py` 用同一套语法走尾部，**47 份分毫不差走到 EOF**
（33 种骨数：14,24,25,28,30,32,36,37,38,41,44,45,46,47,48,54,58,62,63,65,69,
75,80,83,88,90,94,97,101,104,115,118,128），且每一份：

* 条目数 == 头部 0x110 声明数（46=46、25=25、128=128……无一例外）；
* 单根（`000` 或个别 `bip01`）、无环、无孩子被列两次；
* 名字前的那个 u32（条目标志位）分布**恒为 {-1:1, 1:其余}** ——
  「它是父索引」这条旧猜想就此在全库尺度上钉死：它不是父索引；
* 挂点段（`tx_*`）在同一种语法里自然收尾。

没走通的 634 份是另一族尾部变体（以 `w1351_caiji_hamigua_01.mesh` 为代表：
声明 2 骨、只有一条 `bone001` 记录、最后一个条目没有名字段，尾部 0xde8..0x109c
多出一种 64B 块）——如实不认，不影响本结论，留作后续。

## 步骤 3：几何交叉验证 —— 🟢 全过

`parent_walk.py` 对主样本解出的树：

```text
000 → bip01 → {bip01_footsteps, bip01_pelvis}
bip01_pelvis → bip01_spine → {bip01_spine1, bip01_l_thigh, bip01_r_thigh,
                              bone10, bone10_mirror02, bone10_mirror01,
                              bone10_mirror02_mirror01}
bip01_spine1 → {bip01_neck, bone05};  bip01_neck → {bip01_head, l_clavicle, r_clavicle}
l_clavicle → l_upperarm → {l_forearm, bone08};  l_forearm → l_hand → {finger0, finger1, bone09}
（右臂镜像同构）thigh→calf→foot→toe0；bone10→bone11→bone12；bone05→bone06→bone07
```

* 单根 = `000`，46 节点，Σ孩子数 = 45，无环，无重复引用；
* 与 Biped 解剖逐骨一致（含 `_l_`/`_r_` 镜像子树同构）；
* 「父子都有绑定矩阵」的 20 对里，17 对 |Δ位移| ∈ (0.001, 2.0]：
  pelvis←bip01 = **1.0991**、foot←calf = **0.4052**、toe0←foot = **0.5460** ——
  与 2026-09-29 手算的表逐一对上（当时只有距离没有链，如今距离的骨对就是解出的链）；
  spine←pelvis = 1.5902、hand←forearm = 0.3922 也落在带内；
* 三个超 2.0 的例外全是 accessory/长肢链，不是解析错误：
  bone05→bone06 = 3.18（武器链）、r_clavicle→r_upperarm = 2.4485（与 09-29 手算一致）、
  bone10_m02_m01→bone11_m02_m01 = 2.4030。

顺带把三个「像」升级成「证」/「疑」：

* 🟢 `名字 ×2` = 条目自报名两遍，46 组 = 46 根声明骨；
* 🟢 尾部最后一段 = 挂点表 `[u32 4][tx_head→Bip01_Head, tx_wuqi→Bone01,
  tx_chest→Bip01_Spine1, tx_shenti→Bip01_Spine]`，每条 128B，4×128=512B 恰好收口 EOF；
* 🟡 两个语义未证（识别了、没解释）：对角块 88B
  `[d,0,0,0,0]×3+[1.0,0,0,0]+[100,100,100]`（d 逐文件 0.9998 或 1.0）；
  64B 局部矩阵（行主序、前三行正交、末列 0,0,0,1）。后者与 bind 的复合关系
  八种口径全试过（`local∘bind_parent` / 逆阵 / 行列向量），残差 2.3~4.8，
  **不是** bind 的局部变换——是什么，留给下一位。
