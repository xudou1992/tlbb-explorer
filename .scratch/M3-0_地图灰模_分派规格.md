## 0. 开工前必须纠正的三处（否则会写错代码）

> ⚠ 本节已被 **A1 独立复算**（`agent_m3_01_layout.txt`，全量 11,933 个 `.scene`）修正。
> 用户原口径「stride = tag + 8」方向对，但 **base 与 stride 是两个不同的数**，
> 且「矩阵第 4 列 = 0,0,0,1」是错的。

### 0.1 base ≠ stride（A1 全量反例）

```
.scene 头（12 字节）：u32 n_records, u32 tag, u32 zero
base   = 12          ← 恒定，与 tag 无关
stride = tag + 8     ← 随版本变
```

| tag | 文件数 | stride = tag+8 | base | stride−base |
|---|---|---|---|---|
| 753 | 9288 | 761 | 12 | 749 |
| 749 | 940 | 757 | 12 | 745 |
| 605 | 81 | 613 | 12 | 601 |
| 592 | 66 | 600 | 12 | 588 |
| 957 | 21 | 965 | 12 | 953 |
| 596/601/324 | 各 1~2 | 604/609/332 | 12 | — |

**「stride == base」为假，反例 = 全量。** 用户发现的"跟版本走"这个机制是对的，
但那个量是 **stride**，不是 base。`stride-base = tag-4`。

```rust
let base: usize = 12;                      // 观测：10377/10377 首个命中点都在 12
let stride: usize = tag as usize + 8;      // 版本兼容点（用户发现的机制，保留）
```

### 0.2 「矩阵第 4 列 = 0,0,0,1」是错的——是**第 4 行**

A1 逐字段核 **170,748** 条记录：

| 判据 | 结果 |
|---|---|
| `m[3]==m[7]==m[11]==0` 且 `m[15]==1.0`（仿射·末行为 0,0,0,1） | **170748/170748，违反 0** |
| `m[12]==m[13]==m[14]==0`（第 4 列为 0） | **假**——它们不是 0 |

结论：**矩阵是列主序存储**，平移向量在 `m[12], m[13], m[14]`。
`(m[13], m[14])` 落在 `m[12],m[14]` 组合中对上格子坐标 **170747/170748 = 99.99941%**：

```
m[12] = 世界 X      m[13] = 世界 Y      m[14] = 世界 Z
floor(m[12]/32) == 文件名第 2 段        floor(m[14]/32) == 文件名第 3 段
```

（原报告说"第 4 列是位置"这个直觉方向对，但存储序要是列主序才对得上。）

### 0.3 `n_records` 被系统性低估——尾部还有附加段

`u32@0` 是记录数，但**文件尾常还有一段用另一种 stride 的同类记录**（同样满足判据 M+N）。
所以 `size - (12 + stride*n)` 常为负（实测 p50 = **-8**，但 tag=749 的 p50 是 **-165**）。
真记录数 − `u32@0` 分布：`0 → 6723`、`-1 → 1344`、`-2 → 702`……

**所以代码必须「先验后解」，不能只信 `u32@0`：**

```rust
// 判据 M：偏移 o 处是仿射矩阵 —— m[15]==1.0 且 m[3]==m[7]==m[11]==0 且 m[0..12] 有限
// 判据 N：偏移 o+64 处是「可打印 ASCII 相对路径 + .ext + \0」
// 用 M+N 在 { base + i*stride } 上连续走，走多远算多远；
// u32@0 只是"至少有多少条"的提示，不是上界。
```

**布局拒绝条件**（A1 给的 6 条，全部有实测支撑）：
1. `len(raw) < 12` → 拒绝（本库 **1238** 个，4 字节空格子）
2. `n_records == 0` → 合法空格子（本库 0 个）
3. `tag ∉ {753,749,605,592,596,601,324,957}` → 版本未知，拒绝
4. 判据 M/N 在 `12 + i*stride` 上走不通 → **布局不成立，拒绝**（本库 3726 个）
5. `len(raw) < 12+stride*n` → 记录区被截断，谨慎（10300 个）
6. 判据 M/N 能走通但 `i > n_records` → **尾部有附加段，必须继续走**

这条**必须**进测试 —— 见 §4 的 T1/T2/T6。

### 0.4 `.sfl` 不是格子索引（A4 结论，省掉一整条路）

原计划假设 `.sfl` 是「格子坐标 → `.scene`」的索引表。**A4 独立验证：否。**

- 297 个 `.sfl`、12,730 条字符串里，`.scene` 引用 **0 条**，坐标串 **0 条**
- 反证：297 个 `.sfl` 中 292 个的文件名等于同目录某 `.scene` 主名（同构同级，非索引）
- `.sfl` 实为**每图一份的场景光照/天空/雾配置**（字段名如 `Main light color`、`Fog color`、
  `Sky top color`、`Sun Angle`、`Moon0..30 Alpha`、`Fog one/two density`，约 60 个）

**对 M3-0 的影响：不需要 `.sfl` 来遍历格子**——格子清单直接从 DB 里按
`path LIKE 'mobile_maps/<mapId>/%.scene'` 取即可。`.sfl` 留到光照阶段（v0.6）。
