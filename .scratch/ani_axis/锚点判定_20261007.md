🟢 **三条硬结论**：

1. **裸 bind 锚不能播**：15/15 条动作撕裂（帧均 0.84~1.76，全局 max ≈3.8）。
2. **逐动作 frame0 锚（A1）全部胜出**，且没有一条例外。idle 族的残差 0.14~0.26

   但 walk/run/idle02/dead/flyingdeadbegin 明显变差（walk 0.672/2.512 vs 0.142/0.806）。
   **锚必须逐动作取**（或等价地：导出时给每条动作自己的 inverseBind）。

**frame0 跨动作稳定性**（刀 1a 的数字答案）：15 条动作按 frame0 局部分组，
9 条与 idle01 在世界层差 <0.001°（其中 idle01/idle03/vertigo 逐字节同组）；
behit01 只差一根挂件骨 `bone12_mirror02_mirror01`（19.57°，平移 0）；
**walk +164.1°/1.67、run +174.9°/1.67、idle02 +165.5°/1.67、
dead/flyingdeadbegin +177.8°/1.01（max 逐骨）——是半程起步的运动，不是 rest 差异**。
跨怪物复现（hamigua/duchanchu/bosijihao 全组共享、heihou 的 idle02 单独）。

## 二、刀 1(b)：frame0 与 bind 之间差一个什么

**🟢 排除项**（都是数字结论）：

- **不是全局轴差**：48 个带符号置换 Q（t→Qᵀt）扫 frame0 世界位，
  静态重心判据最优 **0.70**（bind 参照 0.1488，raw frame0 1.85），且最优 Q 下
  骨架解剖倒置（head y=0.15 < pelvis y=0.84）。上一班的 R 假设在「位姿」层面不成立。
- **不是「绕 bind 静置的增量」**：12 种（旋转 4 读法 × 平移 3 读法）变体复合
  frame0，最优重心残差 0.56，仍远离 0.1488。
- **不是带符号置换级的逐骨轴**：K 递归（`K_j = L_j(0)⁻¹·K_p·blocal_j`，迫使
  修正局部=bind 局部）解出的 K 是**任意旋转**（clean 骨互差最大 179.6°，
  距最近带符号置换 median 39.6°）。`mat64` 块、静态区 qrest 及其父子组合
  （9 种 battery）与 K 全都不匹配（63°~180°）。

**🟢 新解出的结构——`.ani` 骨架静态区**（anim.rs 里「+48 用途未证」的那 60B/骨记录，
四条真样本口径的 Python 复刻在 `k2_rest.py`）：

| 字段 | 语义（本班钉死） | 证据 |
|---|---|---|
| +12 四元数 qrest | **= bind 局部旋转的逆**（行向量/被动约定的存法：R(qrest)=R(blocal)ᵀ） | xiyuqiezei 15/20 干净骨 <0.01°；跨怪 heihou 13/16、duchanchu 14/16 |
| +48 三浮点 off48 | **= 第一孩子的轨道常量平移**（Max Biped 式「骨长向量」，即子骨 rest 平移） | 28/29（唯一 miss 是 bip01：其 off48 恰= pelvis 的 **bind 局部平移** [−0.0007,0.0507,1.0979]，见 §三） |
| 整区 | **跨动作共享**（属骨架不属动作） | behit01 vs dead 仅 3/2760 字节不同；hamigua/duchanchu 0/1560、heihou 20/1740 |

用 `L_rec(j) = [R(qrest_j)ᵀ, 轨道常量平移_j]` 重建 bind 局部：pelvis 例外的
正序读法修正后，**无记录骨的 rest 旋转从「有记录子孙的真实 bind 世界」反解**
（`W_父 = B_子 · L_rec(子)⁻¹`，k4_solve.py），反解结果与 GLB 独立数据对账：
**20 根干净骨旋转差 max 0.069°、平移差 0.00000**；46 骨修正复合的 frame0 世界
对 30 根记录骨 **|Δt| = 0.00000、角差 max 0.077°** —— 两套骨架在「静置」层面
**精确闭合**。无记录骨重建位 _, spine1 y=**1.264**、neck y=**1.478**、head y=**1.784**，
与 README 的站立解剖高度（胸口 1.270）同量级。

**🟡 未闭合一环**：以上闭合只到「静置」。**运动的帧约定仍未破**——把 K 当逐骨
共轭去修正播放（4 种共轭方向全试），walk 反而变差（0.672 vs A1 0.142），
即 `A_j = C_p⁻¹·Ã_j·C_j` 的逐骨共轭结构**对运动部分不成立**；`mat64` 块
（15 张纯旋转，两模型逐字节同）语义未破。因此「引擎逐帧求值的原始口径」仍是 🔴，
**播放的绝对朝向（刀 4 的 R）继承未证**。

## 三、刀 3：`.ani` 常量偏移与 bind 局部平移是同一个量（翻案）

上一班「29 根有记录骨模长不符（ratio 0.14~1.57）」被本班**翻案**：那是两个假象叠加——

1. **占位污染**：96B 记录缺失的骨（spine1/neck/head/两 thigh/l_clavicle/bone10 族/
   手指等 15~16 根）在现口径下世界=父骨，导致其**子孙**的「bind 局部」被
   `W_child·W_parent⁻¹` 算错（l_upperarm 0.6253、r_clavicle 0.6861 皆此类）；
2. **根运动骨**：pelvis 与 footsteps 是仅有的两根轨道平移跨帧会动的骨
   （std 0.023/0.021），它们的轨道平移是**根运动**，本来就不该等于绑定位移。

把这两类剔掉后（**干净骨 = 自有记录且父有记录，20 根**）：

| 骨 | 轨道常量平移 | bind 局部平移 | 向量差 |
|---|---|---|---|
| bip01_l_foot | [0.4052, 0, 0] | [0.4052, 0, 0] | 0 |
| bip01_r_upperarm | [0.1076, …] | 同 | 0 |
| bip01_r_forearm / r_hand / r_toe0 / bone06 / bone07 / bone12×3 … | 同 | 同 | 0 |

🟢 **干净骨上 `.ani` 轨道平移与 bind 局部平移向量级相等（差=0，15/20 根）——同一个量、
同一坐标系（父骨 bind 系）**。5 根例外各有名目：pelvis（根运动骨，轨道平移是位移
不是骨偏移）、bone01/bone09（武器链：方向一致 0.00°、模长 0.42 倍）、bone08、
bone10_mirror02_mirror01（挂件链，13.9°）。上一班「方向没测」的开口就此关闭：
方向、模长对上了。

🟢 **无记录骨的缺失平移就在 `.ani` 轨道里**（spine1 0.1708、neck 0.2140、head 0.3120、
l_clavicle 0.0951、l_forearm 0.1332、l_finger0 0.3194…），且静态区 off48 以
「第一孩子轨道平移」的形式逐骨复读（28/29），`bip01` 的 off48 直接给出 pelvis 的
bind 局部平移——上一班「缺失 64B 的平移部分很可能就在 .ani 里」升级为实锤。

🟡 **无记录骨的缺失旋转不在已解数据里**：静态区 qrest 对无记录骨不遵循
「=blocal⁻¹」模式（spine1 的 qrest≈0.05°，但其真旋转由子孙反解 ≈86.7°）。
本班用「有记录子孙反推」补齐（见 §二），但这是**每怪一次的求解**，不是直接读数。

## 四、决策回答：v0.5.0 播放基准用什么锚

**🟢 能落码的口径**（按证据强度排序）：

1. **静止渲染**：维持现状——`.mesh` bind（S⁻¹ 口径，重心判据 0.1488），不动。
2. **播放**：**逐动作 frame0 锚**。每个 `.ani` 用自己的第 0 帧世界矩阵的逆当
   inverseBind（three.js 里重算 `skeleton.boneInverses`，或导出侧给每条动作
   写独立 skin/IBM）。证据：15/15 条动作全胜（§一表），双模型一致（其中
   shoutao 恒等），且这是**唯一**同时满足「9 条共享 + 6 条半程」的方案。
3. **界面文案**：动作页/骨架页可注明「播放以该动作第 0 帧为基准；静止显示用
   绑定姿态；两者不同源（frame0≠bind，见档案）」。

**必须标注「未证」的口径**：

- **运动的绝对朝向**：frame0 锚保证连贯、不保证方向正确（K 共轭残差随动作
  幅度显形：deadbegin 重心残差最坏 2.45）。摆位、界面展示可用；「和游戏画面
  逐帧对齐」不能承诺。
- **半程动作的相位**：walk/run 等 6 条以 frame0 为锚时，第 0 帧渲染为绑定姿态
  （引擎里可能是半程姿态起步）——形状对、相位可能差。
- **静态区 rest ≠ 播放锚**：静态区能精确重建 bind（§二），但「引擎是否用它做
  rest-relative 蒙皮」未证（用它的两种尝试都劣于 A1）。

**🔴 继承开口**：引擎逐帧求值的原始口径（mat64 语义、运动帧约定）、全局 R。
下一班最有性价比的一刀：** exe 侧读动画求值函数**（既定方针允许时），或拿
静态区重建的精确 bind + K 表（已存 `k4_K.json`）对照更多怪找规律。
