# 骨架表解不出的分桶普查（2026-10-10）

交接报告 §4 第 2 条：「jiumozhi 型 exporter 缺口——`.ani` 77 骨 15 条俱全但
`.mesh` 骨架表解不出 0 节点，值得单开一班追失败族群（hamigua 之后剩 ~360 份）」。
这一班先把**账量清楚**：361 份不再是一坨 `None`，而是四族，各有特征。

工具：`crates/core/src/bin/hier_census.rs`（跑 `hierarchy_try` 逐份分桶）。
为了让失败带原因，`geometry.rs::parse_hierarchy` 拆成
`hierarchy_try() -> Result<_, &'static str>` + 一层 `parse_hierarchy = .ok()` 包装——
**判据一条没改**（全库回归：`.scratch/rc3 cargo test` 与普查计数 2,335/361 一字不差）。

## 读出来的三件事

1. **最大的一族是「没有起点」那 171 份，而且它们是标准人形**（28/27/32/39/40 根骨）。
   这不是坏数据，是**第三种尾部起手式**——hamigua 那族（`[u32 -1][名字×2]`）是第二种，
   现在这 171 份两样都不占。下一刀就是从 3~4 份样本的尾部字节里把第三种起手式认出来，
   判据仍要「走到 EOF + 条目数 == 声明数 + 单根无环」，不许放水。
   量级参考：hamigua 那一族当年一次走通数 1,439→2,208，这族若拿下能到 ~2,500。
2. **「尾部走不通」那 172 份里 104 份明明有 origin 记录**——起点找到了还走不通，
   说明尾段里存在**我们还没认出的块型**（与 10-06 记档的「64B 局部矩阵块 / 88B 对角块
   语义未证」是同一类东西）。这一族比第 1 族难，别先碰。
3. **「不是单根」那 17 份全是动画道具**（`*_ani_*`、碎玻璃、钟、云）。它们多半是
   **多棵并列的树**（一件道具上挂多个独立动画子树），不是解析坏了。
   这条要单独验：把每份的根名列出来看是不是「一个 origin + 若干挂点根」。
