# `.tani` 取证 · 🟡

解包树 `D:\TLGL\.scratch\out\tree\data\tani` 里 **2560 / 2560** 份都以魔数 `GATA`（`47 41 54 41`）开头，紧跟 **u32 0**。它不是 JBCF、不是 JBPU、也不是 `.ani` 那套信封。

一条文法能把 **2550 / 2560** 份从文件头走到 EOF。剩下 9 份停在 304 字节，1 份的段计数是 3，套不进同一条规则。按「全部样本走到 EOF 才算解出」，结论是 **🟡**。下面的字段是这条文法在 2550 份上反复对上的部分，加上没走通的那 10 份的普查；没有把 `.ani` 的关键帧、四元数、32 字节轨道套过来。

样本是解包树里的明文。清单 `.scratch/resources.db` 只读，用来对路径和 `original`。旧笔记（`.scratch/动画骨架_线索_20260929.md` §3.6）已经写过：类型是 GATA，core 里没有读取器。这次用解包后的字节把这句话核完，并往下多走了一步长度规则。

复算脚本在同一目录：`walk.py`（2550 份的走通）、`census.py`、`probe_*.py`。

## 2. 不是已有容器的另一个实例

对照 `crates/core/src/jbcf/parser.rs`、`crates/core/src/preview/effect.rs` 开头的 JBPU 布局，以及 `crates/core/src/preview/anim.rs` 的 `.ani` 头。三套都在全部 2560 份上对过，命中数为 0。

**JBCF**（`.mtl` / `.mdl` / `.ske` / `.sfl`）的头是 `JBCF`、`+4 = 0`、`+8 = 8`、`+12 = 文件长−16`、`+16` 的块号 86。`.tani` 的 `+4` 也是 0，但魔数是 `GATA`，`+8` 起是路径字符而不是整数 8。`u32@8==8`、`u32@12==文件长−16`、`u32@16==86` 都是 0/2560。全文检索不到 `JBCF` 这四个字节。

**JBPU**（`.pu`）的头是 `JBPU`，`+4` 是字符串条数，后面是 `(长度, 哈希)` 表和字符池。`.tani` 魔数不是 `JBPU`，`+4` 恒为 0。全文检索不到 `JBPU`。

**`.ani`** 的头在 `anim.rs` 里是：

```text
0x00  64B  版权串
0x40  类型标签 "ani"
0x48  u32  版本
0x8C  "MIN2"
0xBA  u16  骨骼数
0xC2  u16  关键帧数
0xF0  骨名，每条 30B
末尾  骨骼数 × 帧数 × 32B 的轨道
```

`.tani` 里版权串 0 份，`MIN2` 0 份。有 4 份在 `0x40` 出现字节 `ani`，那是自身路径扫过这个偏移时 `.tani` 的最后三个字母（例如 `…dian01.tani` 的 `ani` 刚好落在 `0x40`），后面是 NUL，不是类型标签，也没有版权串和 `MIN2`。因此 `.ani` 的骨骼数、帧数、30 字节骨名、32 字节轨道都不在这套字节上，那些结论不搬。

文件里能读到的名字是别的东西：粒子段第一条记录开头是 `.pu` 路径（2400 份，偏移 `0x140`）；音效段槽里是 `.wav`（823 组）或 `.ogg`（470 组）。`bip01` 只在 28 份里出现，是挂点名散落，不是一张 30 字节一条的骨名表。

## 3. 2550 份走通的文法

分支看固定偏移，不看文件名。`0x110` 到 `0x130` 的 32 字节在 **2560/2560** 份里都是 0，路径的 NUL 最远到 76，碰不到这块。

```text
0x00   'GATA'
0x04   u32 0
0x08   C 字符串，自身路径，以 ".tani" 结尾
…      0x4D .. 0x110 未解（见 §5）
0x110  32 字节 0
0x130  分支
```

### 粒子段

条件：`u32@0x130 == 0` 且 `u32@0x134 == 1`。

```text
n  = u32@0x138
并且 u32@0x13c == n     （1..64）
记录从 0x140 起，n 条，每条 0x318（792）字节
```

- `u32@0x10c == 1` 且文件到 `0x140 + n*0x318` 为止：**1574** 份，EOF。
- `u32@0x10c == 2`：粒子段结束后紧跟音效段：**826** 份，音效段走完即 EOF。

这 2400 份的第 0 条记录 `+0` 都是可打印 C 字符串（2400/2400），内容是 `.pu` 路径。后面的记录经常整段是 0，也有 181 条开头不是文本；长度规则不依赖记录内部，内部挂点名没有收成「每条记录必达」的字段，所以不写进文法。抽样里见过 `origin`、`skill_circular_range_small`、`m_bip01_r_hand` 出现在记录中部（有的文件在 `+0xC4`、`+0x130`），只当观察，不当规则。

`0x134` 那个恒定的 1，含义未证。

### 音效段

两种入口，后面是同一块：

- 粒子段走完且 `u32@0x10c == 2`：音效段从粒子段末尾开始（826 份）。
- `u32@0x130 == 1` 且 `u32@0x134 == 4`：没有粒子段，音效段从 `0x130` 开始（150 份）。这 150 份的 `u32@0x10c` 也是 1，和「只有粒子段」同值，区分它们的是 `0x130` 处的分支，不是 `0x10c`。

```text
+0   u32 1
+4   u32 4          这 976 个音效段全部是 4；和下面的 5 槽是否有换算，未证
+8   u32 G          组数
+12  u32            小整数（623 份为 0，223 份为 1，其余更散），含义未证

字节长度 = G * 5 * 1200 + (G - 1) * 16 + 28
```

每组 5 个槽，槽长 1200。路径在槽内 `+0x10`。**1296 组全部是 5 槽同一条路径**（`.wav` 823 组，`.ogg` 470 组，空路径 3 组），0 组例外。组与组之间多出来的 16 字节、以及末尾 28 字节，内容不恒定：有的是 0，有的是 `… 7f 00 00` 这种用户态地址的形状。长度公式把它们算进 EOF，但不把它们命名成已解字段。

`G = 1` 时整段 6028 字节；`G = 2` 时 12044；一直到 `G = 8` 的 48140。这和 §1 里那些成簇的文件长度、以及 40 份清单差额，是同一组数字。

### 和 `0x10c` 的对应

| `u32@0x10c` | 份数 | 走到 EOF 的读法 |
|---:|---:|---|
| 1 | 1724 | 1574 份只有粒子段；150 份只有音效段 |
| 2 | 826 | 粒子段 + 音效段 |
| 0 | 9 | 304 字节那批，数到不了段（§4） |
| 3 | 1 | `boss_tani_liqiushui_shifa07.tani`，套不进上面两段（§4） |

在走通的 2550 份里，这个数等于实际走出的段数（粒子、音效各算一段）。值 3 的那一份对不上，所以它只是和分支一致的计数假设，不是已命名的文件版本号。

## 4. 没走通的 10 份

**9 份，长度正好 304（`0x130`）。** 魔数、`u32 0`、自身路径都在。文件在 `0x130` 结束，而粒子段 / 音效段的分支词就写在 `0x130`。`0x10c` 到文件尾是 0，没有 `n`，也没有 0x318 / 1200 的数组。`0x58` 在其中 6 份是 u32 `8`，`0x80` 和 `0x88` 在这 6 份是 u32 `1`；另外 3 份不是这个形状。中段还有随文件变化的地址形状 u64。这 9 份共享头部魔数和末尾一块 0，不共享那条能走到 EOF 的段文法。

**1 份，`boss_tani_liqiushui_shifa07.tani`，9700 字节。** `u32@0x10c = 3`，`0x130` 起的四个 u32 是 `2, 1, 1, 0`，既不是粒子段的 `0, 1, n, n`，也不是音效段的 `1, 4, G, …`。文件里同时有绝对路径 `E:/tianlongfenzhi/Client/`、字符串 `motion_camera_shake`、一条 `.pu`，以及 5 份间距 1200 的 `lqsJJ_rel.wav`。音效槽的重复还在，但前面多出来的那截没有第二份样本，不能单凭这一份定一条第三段。

## 5. 头部 `0x4D..0x110`：未解

路径 NUL 之后、`0x110` 的全 0 区之前，是固定偏移上的字节，不是「字符串补齐到某个对齐」。700 份在 NUL 的下一字节就不是 0，所以不能当成对齐填充丢掉。

这些 u64 里有一批高位落在 `0x00007FF…` 或 `0x000001xx…`，并且每份文件不一样，对不上文件内偏移。`liqiushui` 那份还嵌了一条盘符绝对路径。因此这块更像对象映像里留下的地址，而不是一张可重定位的偏移表。没有把它解释成计数字段，也没有拿它去切记录。

`0x10c` 在走通的文件里才是上面的段数；304 字节那 9 份此处是 0，因为从这里一直到 EOF 都是 0。

## 6. 和 `.ani` 关键帧结论的界线

`.ani` 能走到 EOF，靠的是版权串、`ani` 标签、`MIN2`、`0xBA`/`0xC2` 的骨骼数和帧数，以及末尾 `骨骼 × 帧 × 32`。这些字节在 `.tani` 里不存在。

`.tani` 能走到 EOF 的部分，是固定头、`n` 条 792 字节的记录（第 0 条以 `.pu` 路径开头），以及按组重复 5 次的 `.wav`/`.ogg` 路径。这是事件/引用槽的长度规则，不是骨骼轨道。记录中间那些浮点和挂点名，没有按「每骨每帧四元数 + 位移 + 缩放」核过，也不引用 `anim.rs` 里 60 份样本、单位四元数、帧率 40.0 那些结论。
